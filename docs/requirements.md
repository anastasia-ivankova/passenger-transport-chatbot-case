# System Requirements

## Назначение системы

Чат-бот предназначен для автоматизации процесса взаимодействия с клиентами при организации заказных пассажирских перевозок. Система позволяет сократить время обработки заявок, снизить операционную нагрузку на руководителя и обеспечить круглосуточную доступность сервиса.

## Пользователи системы

| Пользователь | Описание |
|--------------|----------|
| Клиент | Получает информацию о компании, оформляет и отменяет заказы, управляет профилем, просматривает историю заказов, получает консультацию и оставляет отзыв. |
| Руководитель | Получает результаты работы чат-бота, просматривает сведения о заказчиках, оформленных заказах и сформированные заказ-наряды. |

## Функциональные требования

### Информация о компании

| ID | Требование |
|----|------------|
| FR-001 | Система должна предоставлять пользователю информацию об автотранспортной компании. |
| FR-002 | Система должна предоставлять сведения о перевозчике, лицензии и контактных данных компании. |

### Консультирование

| ID | Требование |
|----|------------|
| FR-003 | Система должна предоставлять ответы на наиболее часто задаваемые вопросы. |
| FR-004 | Система должна предоставлять пользователю возможность отправить собственный вопрос руководителю. |

### Управление заказами

| ID | Требование |
|----|------------|
| FR-005 | Система должна предоставлять пользователю возможность оформить заказ на пассажирскую перевозку. |
| FR-006 | Система должна автоматически формировать заказ-наряд на основании введённых пользователем данных. |
| FR-007 | Система должна предоставлять пользователю возможность отменить оформленный заказ. |
| FR-008 | Система должна предоставлять пользователю возможность просматривать историю своих заказов. |

### Управление профилем заказчика

| ID | Требование |
|----|------------|
| FR-009 | Система должна предоставлять пользователю возможность создать профиль заказчика. |
| FR-010 | Система должна предоставлять пользователю возможность изменять данные профиля заказчика. |
| FR-011 | Система должна предоставлять пользователю возможность удалить профиль заказчика. |

### Обратная связь

| ID | Требование |
|----|------------|
| FR-012 | Система должна предоставлять пользователю возможность перейти на страницу для размещения отзыва о качестве оказанных услуг. |

### Работа с данными

| ID | Требование |
|----|------------|
| FR-013 | Система должна сохранять сведения о заказчиках в базе данных. |
| FR-014 | Система должна сохранять сведения об оформленных заказах в базе данных. |
| FR-015 | Система должна предоставлять руководителю доступ к сведениям о заказчиках, оформленных заказах и сформированным заказ-нарядам. |

## Нефункциональные требования

| ID | Требование |
|----|------------|
| NFR-001 | Время отклика системы на пользовательский запрос не должно превышать 5 секунд при стандартной нагрузке. |
| NFR-002 | Система должна обеспечивать доступность сервиса не менее 99% времени в течение суток. |
| NFR-003 | Система должна обеспечивать круглосуточную доступность основных функций. |
| NFR-004 | Система должна минимизировать вероятность ошибок ввода данных за счёт использования встроенной валидации. |
| NFR-005 | Интерфейс должен быть интуитивно понятным и не требовать предварительного обучения пользователей. |
| NFR-006 | Система должна обеспечивать защиту персональных данных пользователей и ограничивать доступ к базе данных. |
| NFR-007 | Система должна поддерживать увеличение количества обрабатываемых запросов без существенного снижения производительности.
